# EdgeFHE 參考基準點與對照方法（2026-10-24）

這份文件回答一個問題：**我們的專題可以拿什麼來比、怎麼比才公平**。

- 數據集：[REFERENCE_POINTS.json](REFERENCE_POINTS.json)，由 `build_reference_points.py`（開發紀錄，未收錄）產生。
- 我方數字：程式直接從已審查的板上原件重算，原件有雜湊值固定。
- 文獻數字：引用原論文表格，並標出頁碼。
- 換算欄：一律由程式計算，不手打。

## 1. 證據層級（每個數字都要標）

| 層級 | 意思 | 可以怎麼用 |
|---|---|---|
| OUR_BOARD_MEASURED | 我方在 KV260 上量測，原件經獨立審查 | 可以算加速比，也可以下結論 |
| OUR_BOARD_PENDING | 量測包已準備好，還沒在板上跑 | 不能引用數字 |
| AUTHOR_MEASURED_HW | 論文作者在實體硬體上量測 | 只能用來定位（平台與參數都不同） |
| AUTHOR_MEASURED_CITED | 作者量測，但經由另一篇論文的表格轉引 | 同上，並註明轉引 |
| AUTHOR_SIMULATED | 模擬或合成結果，不是實體晶片 | 只能看架構趨勢 |
| DERIVED | 由上述數字換算而來 | 輔助理解，不能當成量測 |

**只有同一塊板、同一組參數、同一種工作量的比較，才能叫「加速比」。** 和論文之間的比較只能叫「定位」。

## 2. 三種比法

### A. 同板因果比較（正式結論只來自這一類）

| 基準 | 內容 | 狀態 |
|---|---|---|
| CPU3：我方最佳化 C++，3 執行緒 | 同一套程式，只把加密改在 ARM 上做 | ✅ 同板 10 session，有信賴區間 |
| OpenFHE 1.5.1（同板） | 現成開源函式庫，參數 N=4096、3 個模數、logQ=91、128-bit | ✅ **B1：同一次開機（e26925f5）、同一個工作量、10 session × 1／3 執行緒，原件審查通過** |
| PL：我方 ARM＋FPGA | V8b，200 MHz | ✅ |

### B. 同參數文獻定位（N=4096、3×30-bit，和我們同一級）

SEAL-Embedded（Microsoft，TCHES 2021）是最直接的軟體對照組，參數和我們完全同級。

### C. 不同參數的 FPGA／ASIC 客戶端加速器

這一類用兩種換算對齊參數後再看：

- **每元素時間**：一個密文的加密時間 ÷ 打包的數值個數（N/2）。這是 Pasta on Edge（EF08 Table III）採用的比法。
- **工作量換算**：以 NTT 工作量 W = N·log₂N·模數個數，換算到 N=4096、3 個模數。這是近似值，只能當推導。

### 這張表能說什麼

1. **和同參數的現成軟體比**：
   - SEAL-Embedded 是 91 ms/密文（A7 494 MHz）；
   - 同板 OpenFHE 為 11.4 ms（A53，B1 同次開機實測）；
   - 我方 CPU3 為 3.3 ms，PL 為 1.2 ms。
   和 SEAL-Embedded 比，因為 CPU 不同，只能算定位；同板的 OpenFHE 對照（B1）則是正式的因果比較：PL 快 9–11 倍。
2. **和 FPGA 客戶端加速器比**：
   - 換算到同參數後，Aloha-HE（Kintex-7）約 0.86 ms/密文，我方 1.2 ms，**同一個量級，Aloha-HE 略快**；
   - Aloha-HE 只用 56 個 DSP，我方用 531 個，所以**我方的 DSP 面積效率約低 12 倍**。
   這一點要誠實寫進報告。
3. **我方的定位**：不是最快或最省面積的加密核心。我們做的是完整、可量測的系統：
   - 249 美元的 KV260 上，ARM＋PL 協同；
   - 解密、TLS 兩機網路、六小時穩定性、正式統計；
   - 即時互動展示。
   Aloha-HE、RISE、Di Matteo 的論文都沒有網路端到端、長時間穩定性或多 session 統計。

## 3b. 同板因果比較：B1 正式結果（同一次開機 e26925f5，10 session）

時間定義：正規化＋編碼＋加密（每個特徵一個密文）。OpenFHE 為未修改的函式庫，我方數據來自同一次開機的有線長測原件，不含網路。比值以 session 為單位，10000 次 bootstrap，兩組 session 獨立重抽。

| 模型／筆數 | OpenFHE 3 執行緒 | 我方 CPU3 | 我方 PL | OpenFHE ÷ CPU3 [95% CI] | OpenFHE ÷ PL [95% CI] |
|---|---:|---:|---:|---:|---:|
| 工業維護 · 1 筆 | 44.9 ms | 13.4 ms | 4.91 ms | 3.35× [3.35, 3.36] | **9.14× [9.10, 9.17]** |
| 工業維護 · 2048 筆 | 45.4 ms | 13.4 ms | 5.01 ms | 3.40× [3.40, 3.40] | **9.07× [9.05, 9.08]** |
| 糖尿病進展 · 1 筆 | 114.0 ms | 32.5 ms | 10.7 ms | 3.51× [3.50, 3.51] | **10.69× [10.67, 10.72]** |
| 糖尿病進展 · 2048 筆 | 114.5 ms | 34.4 ms | 11.9 ms | 3.33× [3.31, 3.34] | **9.67× [9.61, 9.72]** |

- OpenFHE 單執行緒更慢，約為 PL 的 9.9–11.8 倍。
- 解密（1 個密文）：OpenFHE 3 執行緒 12.6 ms，我方 1.7–2.9 ms；OpenFHE ÷ 我方 = 4.3–7.6×。
- 雲端加權和：OpenFHE 在 A53 上要 2.2–9.9 ms；我方雲端在 PC 上只要 0.12 ms。兩者平台不同，只作參考。
- 所有 OpenFHE 結果都通過明文比對：最大誤差 3.5×10⁻⁴，低於容許值。FPGA 中斷數前後都是 2,879,221，證明 OpenFHE 沒有用到 FPGA。
- 金鑰產生：OpenFHE 約 9 ms。

**結論**：在同一塊板、同一次開機、同樣的參數級別和工作量下，現成函式庫 OpenFHE 的加密約是我方 FPGA 路徑的 **9–11 倍**時間，是我方最佳化 CPU 的 **3.3–3.5 倍**時間。這是專題中「比現成軟體快多少」的正式答案。

## 5. 用基準檢查提案的說法

| 提案原文 | 實際數據 | 結論 |
|---|---|---|
| 「ARM 上一次加密要好幾秒」 | 同參數（N=4096）：SEAL-Embedded A7 為 91 ms；同板 A53 上 OpenFHE 為 11.4 ms（B1）；我方 CPU3 3.3 ms、PL 1.2 ms。只有 Cortex-M4 達 737 ms（SEAL-Embedded 摘要） | **N=4096 時不成立**。報告要改成「毫秒到數百毫秒，視處理器而定」 |
| 「密文是明文的 10–100 倍」 | 一個特徵密文 = 6×4096×4 B = 96 KiB。2048 筆 float64 = 16 KiB → **6 倍**；float32 → 12 倍；只放 1 筆時 → 12,288 倍 | 滿槽時大約 6–12 倍，**打包不滿時會暴增**。這也是我們做 2048 筆批次的理由 |
| 「純硬體做法耗用過多 LUT」 | Aloha-HE 純硬體（含編碼）只用 17.7k–20.7k LUT；我方軟硬體分工反而用了 53k LUT | **不成立**。我方分工的優點應改寫成：編碼留在 ARM 的浮點運算、硬體專注 NTT／取樣、管線吞吐、整套系統可驗證，而不是省 LUT |
| 「明顯快於純軟體」（MVP） | 同板 W1 延遲 2.7–4.2×、W2 吞吐 2.6–3.9×；兩機含網路 1.6–2.0× | ✅ 成立（同板因果比較，有信賴區間） |
| 「使用者在 PC 輸入敏感資料 → FPGA 加密 → 雲端推論 → 解密」 | 即時展示已上板，13 筆全部審查通過 | ✅ 成立 |
| 「即時產生旋轉因子以省 BRAM」 | HLS 已驗證，但沒有整合進板上 bitstream | ❌ 未完成（列為可選加分）；Aloha-HE 已有產生式版本可參考 |

## 6. 對照方法的細節與限制

- **工作量換算**（W = N·log₂N·L）只考慮 NTT 次數，沒有考慮模數位元寬度：54-bit 乘法比 30-bit 貴。所以把 Aloha-HE 換算到我方參數時，它的數字其實偏保守。換算結果只能當推導。
- **每元素時間**假設每個密文打包 N/2 個數值。我方滿槽是 2048 個；Aloha-HE 的 N=8192，所以是 4096 個。
- 我方 PL 的時間包含 ARM 端的正規化和編碼。Aloha-HE 的時間也包含編碼，計算範圍相近。
- 我方 CPU3 的最佳化程度和 PL 相同（公平基準）。OpenFHE 是未修改的函式庫。
- 論文數字沒有變異量，也沒有多 session 統計，所以只能定位，不能做統計比較。

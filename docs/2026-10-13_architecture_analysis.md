# 2026-10-13 架構分析筆記

整理今天的分析：分量（limb）是什麼、目前的平行結構、多方門檻（M）方案、真實進度、報告用詞，以及 V5 做了什麼。

## 1. 分量（limb）：把大數拆成三個小餘數

- 密文係數是 mod Q 的整數，Q = q0·q1·q2 ≈ 2^88.6。資料放大 2^29、乘權重再放大 2^29，結果在 2^58 量級，還要留空間不能溢位，所以需要約 89 位元。
- FPGA 的 DSP 乘法器是 27×18 位元，直接做 89 位元乘法很貴。解法是中國餘數定理：只記住除以三個質數（998244353、1004535809、469762049，都小於 2^30，且除以 8192 餘 1，可做長度 4096 的 NTT）的餘數，每一份稱為一個分量。
- 加、減、乘、NTT 可以各分量獨立計算；比大小、除法、四捨五入不行，所以只有解密最後一步（`centered()`）要合併回大數。
- 和正統 RNS-CKKS 的差別：正統做法每次密文乘法都要 rescale，丟掉一個分量；我們只有一層「密文 × 公開權重」，從不 rescale，三個分量只是一個夠大的容器。

## 2. 目前的平行結構（四層）

| 層 | 實作 | 位置 |
|---|---|---|
| ARM／FPGA 分工 | ARM：編碼、取樣、組裝、CRT；FPGA：NTT、乘法、加減 | 全系統 |
| 分量平行 | FPGA 3 個引擎（HLS DATAFLOW）；C++ 3 個 worker | `rns_ntt_parallel_rns3.cpp`、`core.cpp` |
| 通道平行 | 每個引擎 4 條蝶形通道、4 個 bank，II=1 | `rns_ntt_parallel_core.cpp` |
| 串流管線 | unpack／計算／pack 用 FIFO 重疊 | HLS top |

**關鍵發現**：一次 NTT 的理論計算時間是 12 層 × 515 拍 × 10 ns ≈ 0.06 ms，但實測 FPGA 呼叫要 2.70 ms，約 98% 的時間不是蝶形運算：包含核心內部的載入與旋轉因子產生，以及核心外的打包、ioctl、DMA、解包。乘法呼叫 5.03 ms 裡，整個核心的最差延遲也只有 1.16 ms，所以至少 75% 花在核心外面。瓶頸是搬資料，加寬硬體幫助有限。

另外兩個程式碼層面的問題：
- FPGA 路徑每次乘法都重送公鑰並重新轉換：每個分量 24 次轉換，CPU 路徑只要 14 次。
- V4 的 3 執行緒只快 1.45 倍：編碼、解碼、CRT 不能拆，而且每次呼叫都新建執行緒。

## 3. 多方門檻 CKKS（M 方案）

- **目的**：分散信任，不是加速。私鑰拆成 s = sA + sB + sC，每塊板一份，三份湊齊才能解密。
- **與現有程式的對應**：
  - `keygen()` 本身就是 −a·s + e，三板共用同一個 a 就能各自產生 bi，相加得到聯合公鑰。
  - `encrypt()` 和雲端 `affine()` 不用改。
  - 解密拆成「各板算部分解密 c1·si 加遮蔽雜訊」與「合併」。
  - FPGA 硬體不需要修改。
- **風險**：
  1. **遮蔽雜訊不能省**：c1 是公開的，如果直接送出 c1·si，別人在 NTT 域做一次除法就能算回 si。
  2. **精度和安全很難兼顧**（粗估，需正式分析）：現有雜訊乘上權重後約 2^36–2^40，結果的 1.0 對應 2^58。統計遮蔽要比原雜訊大很多倍（教科書做法約 2^40 倍），目前 Q≈2^88 的參數下幾乎沒有空間。
  3. **雜訊上界要重算**：`no_wrap_bound()` 裡的 +2064（= 16·64 + 16·64 + 16）是單一私鑰的雜訊；三方約變成 3 倍，再加遮蔽雜訊。合併後的 s 也不再是 64 個 ±1。
  4. **協定問題**：三板如何產生共同的 a、n-of-n 時任一板離線就無法解密、惡意板可能送假結果。
- **時間線**：三板同時算，但每板工作量等於單板解密，所以延遲 = 單板 + 兩趟網路 + 等最慢的板。**M 一定比單板慢。**
- **建議**：先確認教授是否把它算進範圍；要做的話，先用 3 個 CPU process 驗證協定，並先做雜訊預算分析。若主軸是邊緣加速，H（管線）比 M 更對症。

## 4. 進度報告 vs 實際狀況

| 項目 | 報告寫的 | 實際查到的 |
|---|---|---|
| FPGA 核心 | 完成 | G01–G06 通過；6 小時 5,798,822 次 soak |
| FPGA 加速 | 乘法 1.31× | NTT／INTT 反而比 ARM 慢 |
| V4 C++ | 完成 | 只在 x86 WSL 上驗證，`board operations = 0` |
| V4 → FPGA | 未驗證 | 有寫 `fd>=0` 的程式路徑，但完全沒有測試證據（V5 已補上模擬測試與 `v5_parity`） |
| 兩機 | 本機 loopback | V3 固定 6 例兩機已通過；V4 任意輸入只在本機測過 |
| 安全 | 不宣稱 | secret 64 個 ±1、error 只有 16 個 ±1，屬於功能 profile |

**報告用詞建議修正**：
- 5.4 節「確保雲端對明文完全盲目」和 6.4 節「安全性未正式估算」互相矛盾 → 改成「雲端只收到密文（功能層面）」。
- 2.2 節說 twiddle「即時生成」，5.2 節又說 on-the-fly「尚未完成」→ 實際上 recurrence／cache 已經實作，還沒做的是和 ROM 的資源比較實驗。

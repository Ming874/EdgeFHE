EdgeFHE 能耗探針實作手冊

ESP32 + INA228：接線、程式實作與校正

版本 2026-11-23　·　適用：KV260、INA228 模組（分流電阻 R015）、GST60A12-P1J 變壓器

0　這支探針做什麼

探針串接在 KV260 的 12 V 電源線上，量測整塊板子的電壓、電流、功率與累積能量。板上的 INA260 只量 SOM 電源軌，探針補上整板的數字，用來驗證專題「每焦耳處理筆數」的主張。

工作分三個階段，依序完成：

階段內容完成標準
1　接線電源線路串入 INA228；訊號線接到 ESP32通電前檢查全部通過
2　實作寫入程式，讀出電壓、電流、功率、能量KV260 待機時讀到約 12.1 V、約 7.1–7.3 W
3　校正與參考儀器比對，求出修正係數並寫回程式修正後與參考值差距 ≤ 1%

1　材料清單

項目規格狀態

DC 公頭電源線5.5 × 2.5 mm，一頭插頭、一頭紅黑裸線（插入 KV260）；也可剪斷公對公線自製（第 3.1 節）已有
連接線Qwiic 轉杜邦線或杜邦線數條；電工膠帶或接線端子依需要

參考儀器校正用：實驗室桌上型電表、電源分析儀或 Joulescope JS220向實驗室借

2　安全規則

  1. 12 V 只接到 INA228 的綠色端子，絕不能碰到 ESP32、顯示面板或 Pmod 的任何腳位。ESP32 的腳位最高只能承受 3.3 V。
  2. 先接線、再檢查、最後才插變壓器。改接線之前一律先拔掉變壓器。
  3. ESP32 由電腦 USB 供電，不從 KV260 取電，否則探針自己的耗電會被算進 KV260。
  4. 插頭尺寸不可混用：母座線 2.1 mm 只配 GST60A12-P1J；插入 KV260 的必須是 2.5 mm 公頭。尺寸不合會接觸不良，KV260 可能突然斷電。
  5. 裸線接點用電工膠帶或接線端子包好，避免正負極相碰短路。

3　接線

3.1　電源線路：讓正極電流繞過 INA228

INA228 就像裝在水管上的水表：只有正極線要斷開，兩端分別接到綠色端子的 Vin+ 與 Vin−；負極線直接連到 KV260，不經過模組。

  1. 母座線的紅線鎖進綠色端子 Vin+。
  2. 公頭線的紅線鎖進綠色端子 Vin−。
  3. 母座線與公頭線的兩條黑線互相接上。
  4. 從這個黑線接點再拉一條細線到 INA228 排針的 GND，三條線一起用接線端子或膠帶包好。INA228 量電壓時以這個負極為基準。
紅線一定是正極嗎？不一定。接之前用三用電表確認：母座中心那根針要導通到紅線；公頭的中心針也要導通到紅線。若相反，就以導通中心針的那條線當正極。
公頭線長怎樣？沒有的話怎麼辦？公頭線是「一頭金屬插頭、一頭紅黑裸線」，和 TG-E1126 同款，只是母座換成插頭。兩頭都是插頭的公對公線或延長線不能直接用，但可以自己剪：全部拔電後從中間剪斷，保留 5.5 × 2.5 插頭那一半；剝開外皮、分出兩條線，各剝約 5–7 mm；用三用電表找出導通插頭中心針的那條當正極；銅絲扭緊（有烙鐵就上錫）再鎖進端子；另一半的裸線頭用膠帶包好。

3.2　VBus 設定：讓 INA228 量得到電壓

量正極側（高側量測）時，VBus 必須接到 Vin+。模組背面的 VBus 跳線焊點出廠時是斷開的。擇一處理：

  • 用烙鐵把背面 VBus 跳線焊點焊通；或
  • 用一條短線把排針上的 VBus 接到綠端子的 Vin+。

沒有接的話，電壓會讀錯，功率與能量也會跟著錯。

3.3　訊號線：INA228、顯示面板與 ESP32

INA228 走 I²C（2 條訊號線），ILI9341 走 SPI（5 條訊號線），兩組各接各的腳位，互不干擾。螢幕以 2.4 吋 8 腳模組（腳位 GND、VCC、SCL、SDA、RES、DC、CS、BL）為準。以下以 ESP32-S3 N16R8 為例。

3.4　通電前檢查（變壓器尚未插上）

  • 三用電表電阻檔：Vin+ 到 Vin− 約 0 Ω（分流電阻只有 0.015 Ω）。
  • Vin+ 到 GND 不可為 0 Ω（不能短路）。
  • 母座中心針導通紅線；公頭中心針導通紅線。
  • VBus 已接到 Vin+。
  • 兩條黑線與 INA228 的 GND 細線已相接並絕緣；裸露的金屬不會互相碰到。
  • 12 V 的線沒有任何一條接到 ESP32、顯示面板或 Pmod。
  • ILI9341 的 VCC 與 BL（LED）接到 ESP32 的 3V3；螢幕的 SCL、SDA 接到 GPIO 12、11。

4　實作：程式

4.1　安裝開發環境

  1. 安裝 Arduino IDE 2。
  2. 開發板管理員搜尋 esp32，安裝 Espressif Systems 的版本。
  3. 「工具」選單設定：開發板選 ESP32S3 Dev Module；Flash Size 選 16MB；PSRAM 選 OPI PSRAM；其他維持預設。
  4. USB 線插在板子上標示 COM 的孔（USB CDC On Boot 維持 Disabled）。若插在標示 USB 的孔，USB CDC On Boot 要改成 Enabled，否則序列埠看不到輸出。
  5. 程式庫管理員搜尋 INA228，安裝 Adafruit INA228 Library（作者 Adafruit，會一併安裝 Adafruit BusIO），本手冊依 3.0.0 版撰寫。
  6. 程式庫管理員安裝 Adafruit ILI9341（會一併安裝 Adafruit GFX），1.6.3 與 1.7.0 版皆可。
  7. 已在 Arduino IDE 2.3.11、ESP32 開發板套件 3.3.12 上以「ESP32S3 Dev Module（16MB、OPI PSRAM）」完整編譯 probe.ino，COM 孔與 USB 孔兩種設定皆無錯誤。

4.2　先做低電壓測試（建議）

公頭線還沒買到前，可以先用 ESP32 自己的 3.3 V 點亮一顆 LED，確認接線與程式都正確，全程沒有 12 V：

ESP32 3V3 ─► Vin+ [INA228] Vin− ─► LED 長腳 ─ LED 短腳 ─► 330 Ω 電阻 ─► ESP32 GND
（VBus 接 Vin+；INA228 的 VCC、GND、SDA、SCL 照第 3.3 節接到 ESP32）

上傳 4.3 節的程式後，序列埠與螢幕應顯示電流約 3–5 mA、電壓約 3.3 V。看得到數字就代表 I²C、顯示面板與量測都正常。

4.3　主程式

程式在 repository 中完整程式在 energy_probe/firmware/probe/probe.ino，用 Arduino IDE 直接開啟即可。不要從這份 PDF 複製程式，縮排和符號可能跑掉。

這是完整程式，已包含顯示面板。只需改最上面兩處：腳位，以及第 5 章求出的校正值。程式每 100 ms 從序列埠輸出一行 CSV，每 0.5 秒更新一次螢幕；在序列埠送出字元 r 會把能量歸零。

// EdgeFHE 能耗探針：ESP32-S3（N16R8）+ INA228（R015）+ ILI9341 顯示面板
#include <Wire.h>
#include <SPI.h>
#include <Adafruit_INA228.h>
#include <Adafruit_GFX.h>
#include <Adafruit_ILI9341.h>

// ===== 1. 腳位（ESP32-S3 N16R8）=====
const int SDA_PIN = 17, SCL_PIN = 18;                      // INA228：I2C
const int TFT_SCK = 12, TFT_MOSI = 11, TFT_MISO = 13;      // ILI9341：SPI
const int TFT_CS = 10, TFT_DC = 14, TFT_RST = 4;
// 不可使用：GPIO 26–37（快閃記憶體與 PSRAM）、0／3／45／46（開機設定腳）、
//          19／20（原生 USB）、43／44（序列埠）、48（板上 RGB LED）

// ===== 2. 校正值：第 5 章求出後填入 =====
const float K_I = 1.0000;          // 電流增益
const float K_V = 1.0000;          // 電壓增益
const float I_OFFSET_mA = 0.0;     // 零點偏移（mA）

Adafruit_INA228 ina228;
Adafruit_ILI9341 tft(TFT_CS, TFT_DC, TFT_RST);

// ===== 3. 每焦耳筆數：電腦經序列埠送指令 =====
//   S<文字>               標題下方的狀態列，例如 SIDLE、SRUN V8b (FPGA)
//   B                     一輪開始：能量歸零
//   E<列>,<名稱>,<筆數>    一輪結束：用這段期間的能量算「筆/J」，顯示在螢幕底部第 <列> 行（0、1 或 2）
String cmdBuf;

void tftInit() {                   // 畫出固定的標題與欄位名稱
  SPI.begin(TFT_SCK, TFT_MISO, TFT_MOSI, TFT_CS);   // 明確指定 SPI 腳位
  tft.begin();
  tft.setRotation(1);              // 橫向 320 x 240
  tft.fillScreen(ILI9341_BLACK);
  tft.setTextSize(2);
  tft.setTextColor(ILI9341_CYAN);
  tft.setCursor(10, 8);
  tft.print("EdgeFHE Power Probe");
  const char* labels[] = {"Voltage", "Current", "Power", "Energy"};
  tft.setTextColor(ILI9341_LIGHTGREY);
  for (int k = 0; k < 4; k++) { tft.setCursor(10, 50 + k * 40); tft.print(labels[k]); }
}

void tftShow(float v, float i_mA, float p_mW, float e) {   // 更新四個數值
  char buf[16];
  tft.setTextSize(3);
  tft.setTextColor(ILI9341_WHITE, ILI9341_BLACK);   // 帶背景色：蓋掉舊數字，不閃爍
  snprintf(buf, sizeof buf, "%7.3f V ", v);           tft.setCursor(130, 45);  tft.print(buf);
  snprintf(buf, sizeof buf, "%7.1f mA", i_mA);        tft.setCursor(130, 85);  tft.print(buf);
  snprintf(buf, sizeof buf, "%7.3f W ", p_mW / 1000); tft.setCursor(130, 125); tft.print(buf);
  snprintf(buf, sizeof buf, "%7.1f J ", e);           tft.setCursor(130, 165); tft.print(buf);
}

void showState(const String& s) {                  // 標題下方：目前狀態（閒置或正在跑哪一版）
  char buf[26];
  snprintf(buf, sizeof buf, "%-25s", s.c_str());
  tft.setTextSize(2);
  tft.setTextColor(ILI9341_GREEN, ILI9341_BLACK);
  tft.setCursor(10, 27);
  tft.print(buf);
}

void showResult(int row, const String& label, double recPerJ) {   // 螢幕底部：名稱與每焦耳筆數
  char buf[32];
  snprintf(buf, sizeof buf, "%-8s %7.0f rec/J", label.c_str(), recPerJ);
  tft.setTextSize(2);
  tft.setTextColor(ILI9341_YELLOW, ILI9341_BLACK);
  tft.setCursor(10, 192 + row * 16);
  tft.print(buf);
}

void handleLine(const String& line) {
  if (line.startsWith("S")) {                          // 狀態列
    showState(line.substring(1));
    return;
  }
  if (line == "B") {                                   // 一輪開始
    ina228.resetAccumulators();
    Serial.println("# run begin");
    return;
  }
  if (line.startsWith("E")) {                          // 一輪結束：E<列>,<名稱>,<筆數>
    int c1 = line.indexOf(','), c2 = line.indexOf(',', c1 + 1);
    if (c1 < 0 || c2 < 0) return;
    int row = line.substring(1, c1).toInt();
    String label = line.substring(c1 + 1, c2);
    double records = line.substring(c2 + 1).toDouble();
    double e = K_V * K_I * ina228.readEnergy();        // 這一輪的能量（J）
    double rpj = e > 0 ? records / e : 0;
    Serial.printf("# result %s records=%.0f E_J=%.3f rec_per_J=%.1f\n", label.c_str(), records, e, rpj);
    showResult(row < 0 ? 0 : (row > 2 ? 2 : row), label, rpj);
  }
}

void setup() {
  Serial.begin(115200);
  delay(500);
  tftInit();
  showState("State: --");
  Wire.begin(SDA_PIN, SCL_PIN);
  if (!ina228.begin(0x40, &Wire)) {
    Serial.println("# ERROR: INA228 not found. Check SDA/SCL/VCC/GND.");
    tft.setTextSize(2);
    tft.setTextColor(ILI9341_RED, ILI9341_BLACK);
    tft.setCursor(10, 215);
    tft.print("INA228 not found");
    while (true) delay(1000);
  }
  ina228.setShunt(0.015, 2.7);                 // R015 = 0.015 Ω，最大 2.7 A
  ina228.setADCRange(1);                       // ±40.96 mV 量程，解析度約 5 µA
  ina228.setMode(INA228_MODE_CONT_BUS_SHUNT);  // 連續量測電壓與電流
  ina228.setCurrentConversionTime(INA228_TIME_540_us);
  ina228.setVoltageConversionTime(INA228_TIME_540_us);
  ina228.setAveragingCount(INA228_COUNT_16);   // 每筆約 17 ms
  ina228.resetAccumulators();                  // 能量歸零
  Serial.println("# t_ms,V,I_mA,P_mW,E_J");
}

void loop() {
  static uint32_t last = 0, lastTft = 0;
  while (Serial.available()) {                 // 讀電腦送來的指令
    char c = Serial.read();
    if (c == 'r' && cmdBuf.length() == 0) {    // 單一字元 r：能量歸零（probe_log.py 使用）
      ina228.resetAccumulators();
      Serial.println("# energy reset");
    } else if (c == '\n') {
      cmdBuf.trim();
      handleLine(cmdBuf);
      cmdBuf = "";
    } else if (c != '\r' && cmdBuf.length() < 40) {
      cmdBuf += c;
    }
  }
  if (millis() - last < 100) return;          // 每 100 ms 輸出一筆
  last = millis();
  float v = K_V * ina228.getBusVoltage_V();                  // V
  float i = K_I * (ina228.getCurrent_mA() - I_OFFSET_mA);    // mA
  float p = v * i;                                           // mW
  float e = K_V * K_I * ina228.readEnergy();                 // J
  Serial.printf("%lu,%.4f,%.2f,%.1f,%.3f\n", (unsigned long)last, v, i, p, e);
  if (last - lastTft >= 500) { lastTft = last; tftShow(v, i, p, e); }   // 每 0.5 秒更新螢幕
}
程式的兩個重點能量用 INA228 晶片內的累加暫存器在硬體裡連續積分，不受 ESP32 讀取間隔影響。能量的修正係數是 K_V × K_I；零點偏移很小時（見第 5.2 節）對能量的影響可以忽略。

4.4　顯示面板（ILI9341）

4.3 節的程式已包含顯示功能，接線照第 3.3 節即可。螢幕由上到下是：標題、狀態列（綠字）、四行量測值、三行每焦耳筆數（黃字）。

欄位意義
Voltage12 V 線上的電壓（V）
Current流進 KV260 的電流（mA）
Power整板功率（W）＝電壓 × 電流
Energy從上次歸零起累積的能量（J）；送出 r、B 或執行 4.5 節腳本時歸零
狀態列（綠字）目前板子在做什麼，例如 IDLE (V8b loaded)、RUN V8b (FPGA)；由電腦送 S 指令更新
rec/J（黃字）最近一輪的每焦耳處理筆數；第 0 行 V8b、第 1 行 OpenFHE 單執行緒、第 2 行 OpenFHE 4 執行緒（4.7 節）

內建字型只支援英數字，所以欄位名稱用英文。若 INA228 沒有回應，螢幕下方會出現紅字 INA228 not found，依第 7 章檢查 I²C 接線。狀態列與每焦耳筆數都由電腦經序列埠送指令更新（4.7 節）。

4.5　記錄資料（電腦端）

校正時要取一段時間的平均值。腳本在 energy_probe/pc/probe_log.py（需要 Python 與 pyserial）。它會先把能量歸零，記錄指定秒數，存成 CSV，最後印出平均值。不加任何參數執行時，會列出目前的序列埠，方便找出 ESP32 是哪一個 COM。

cd energy_probe\pc
python probe_log.py                    # 列出序列埠
python probe_log.py COM5 30 idle.csv   # 記錄 30 秒，存成 idle.csv

腳本內容如下（僅供閱讀，請直接執行 repository 中的檔案）：

"""EdgeFHE 能耗探針：電腦端記錄腳本（手冊第 4.5 節）

用法：python probe_log.py COM5 30 idle.csv
  COM5      換成 ESP32 的序列埠
  30        記錄秒數
  idle.csv  輸出檔名

不加任何參數執行時，會列出這台電腦目前的序列埠。
"""
import sys
import time

import serial
from serial.tools import list_ports

# 這台 Windows 的預設編碼不是 UTF-8，先統一成 UTF-8，中文輸出才不會出錯
for stream in (sys.stdout, sys.stderr):
    if hasattr(stream, "reconfigure"):
        stream.reconfigure(encoding="utf-8", errors="replace")

if len(sys.argv) != 4:
    print(__doc__)
    print("目前的序列埠：")
    for p in list_ports.comports():
        print(f"  {p.device}  {p.description}")
    sys.exit(1)

port, secs, out = sys.argv[1], float(sys.argv[2]), sys.argv[3]
rows = []
with serial.Serial(port, 115200, timeout=1) as s, open(out, "w") as f:
    time.sleep(2)
    s.reset_input_buffer()
    s.write(b"r")                      # 能量歸零
    time.sleep(0.3)
    f.write("t_ms,V,I_mA,P_mW,E_J\n")
    t0 = time.time()
    while time.time() - t0 < secs:
        line = s.readline().decode(errors="ignore").strip()
        parts = line.split(",")
        if line.startswith("#") or len(parts) != 5:
            continue
        f.write(line + "\n")
        rows.append([float(x) for x in parts])

if not rows:
    sys.exit("沒有收到資料：請確認序列埠名稱，以及 ESP32 已上傳 4.3 節的程式")

n = len(rows)


def avg(k):
    return sum(r[k] for r in rows) / n


print(f"筆數 {n}｜平均電壓 {avg(1):.4f} V｜平均電流 {avg(2):.2f} mA｜"
      f"平均功率 {avg(3) / 1000:.4f} W｜累積能量 {rows[-1][4]:.3f} J")

4.6　第一次接上 KV260

  1. ESP32 接電腦 USB，打開序列埠監控視窗（115200），確認沒有出現 ERROR。
  2. 公頭先不要插 KV260，插上變壓器：應讀到電壓約 12 V、電流接近 0。這時的電流就是零點偏移，記下來（第 5.2 節）。此時公頭帶有 12 V，不要讓插頭碰到金屬。
  3. 拔掉變壓器，把公頭插進 KV260，再插上變壓器讓 KV260 開機。
  4. 待機時應讀到約 12.1 V、約 0.59 A、約 7.1–7.3 W（2026-11-23 實測）。簡報第 9 頁的「約 3.5 W」是板上 INA260 量的 SOM 供電軌，只占整板約一半，兩者量的是不同的點。

5　校正

校正的目的：讓探針的讀值與一台更準的參考儀器一致，並留下紀錄，證明探針的數字可信。

參考儀器要比探針準目標是 1% 以內，參考儀器的準確度最好再好 3–4 倍（約 0.3% 以內），例如實驗室的桌上型電表、直流電源分析儀或 Joulescope JS220。一般手持三用電表只適合做檢查，不適合當正式校正的依據。

5.1　參考儀器怎麼接

  • 量電流：參考儀器的電流檔串在正極線上，例如母座紅線與 Vin+ 之間。這樣參考儀器與 INA228 量的是同一個電流。
  • 量電壓：參考儀器的電壓檔量 Vin+ 對負極（黑線）。
  • 電源分析儀或 JS220 可同時量電壓、電流與功率，依儀器說明串接即可。

5.2　步驟 1：零點偏移

公頭不接 KV260（沒有負載），插上變壓器，記錄 30 秒平均電流，即為 I_OFFSET_mA。若絕對值小於 0.3 mA（約為 KV260 待機電流的 0.1%），可直接當作 0。

5.3　步驟 2：電壓增益

同一個狀態下，比較參考儀器的電壓 Vref 與探針的電壓 V探針：

K_V = V_ref ÷ V_探針

5.4　步驟 3：電流增益（穩定負載）

電流最好在穩定的負載下校正，數字不會跳動：

  • 首選：實驗室的直流電子負載，設定 0.3 A、0.6 A、1.0 A 三個點。
  • 替代：大功率水泥電阻，例如 24 Ω／10 W 約 0.5 A（發熱約 6 W，請放在不可燃的表面上，量完立刻斷電）。

每一點記錄 30 秒平均，計算：

K_I = I_ref ÷ (I_探針 − I_OFFSET)　　（各點的 K_I 取平均）

各點的 K_I 應該很接近。若彼此差異大於 0.5%，代表接線或接觸有問題，先排除再繼續。

5.5　步驟 4：用 KV260 實際工作狀態驗證

把 K_I、K_V 填入程式並重新上傳，然後量 KV260 的三個狀態，每個狀態用 probe_log.py 記錄 30 秒，並同時讀取參考儀器的 30 秒平均：

狀態怎麼產生
待機KV260 開機後不執行任何程式，等 2 分鐘讓溫度穩定
ARM 全速sudo apt install stress-ng，再執行 stress-ng --cpu 4 --timeout 90s
PL 連續加密執行 V8b 的連續加密量測（指令請 V8b 作者依 v8b_rev5/README.md 第 7 節提供）

5.6　步驟 5：能量驗證

在 PL 連續加密狀態下，用 probe_log.py 記錄 60 秒。探針的累積能量要等於參考儀器的「平均功率 × 60 秒」（或參考儀器直接顯示的能量）。

8　下一步：接上 Pmod 標記

校正完成後，探針就能量「整板平均功率」。要算出每焦耳處理筆數，還需要知道每一批工作從什麼時候開始、什麼時候結束：

  1. FPGA 端由冠興把「frame 進行中」「批次標記」「200 MHz ÷ 1,024」三個訊號輸出到 Pmod J2。
  2. ESP32 用 GPIO 讀取這些標記（同時把 ESP32 的 GND 接到 Pmod J2 的 GND 腳），在每批開始與結束時記錄 INA228 的累積能量。
  3. 每焦耳處理筆數 ＝ 處理筆數 ÷ 能量差；CPU 路徑與 PL 路徑各量 10 次，報告 95% 信賴區間。

這個做法與 MLPerf Tiny 論文的能耗量測方式相同：受測板子用 GPIO 標記開始與結束，外部能量儀同時記錄功率。
